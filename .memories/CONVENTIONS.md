# CONVENTIONS — стиль и инварианты

Last updated: 2026-07-22

## Стиль кода

- **Java 25**, Paper API. Никакого NMS/рефлексии — только публичный API.
- **Скобки Allman** (открывающая на своей строке) — как во всём коде базы.
  Короткие guard-ветки в одну строку: `if (x == null) {return;}`.
- **Импорты, а не FQN.** Никаких инлайновых `net.kyori.adventure...Foo x` — всегда
  `import`. Группы: `java` → `ru.kiviuly` → `net.kyori` → `org.bukkit`. При
  коллизии имён (например, adventure `BossBar` vs `org.bukkit.boss.BossBar`, наш
  `menu/Menu` vs чужие) импортируй тот, что чаще в файле; второй — полным именем.
- **Пакеты по подсистемам** (`arena/`, `game/`, `menu/`, `stats/`, `ui/`,
  `util/`…), без god-utils.
- **Комментарии/Javadoc — по-русски**, только там, где код сам не объясняет.
  Это шаблон: пиши так, чтобы автор новой игры понял, куда встраиваться.

## Инварианты (не ломать)

1. **Тексты игрокам — ТОЛЬКО из `messages.yml`** (MiniMessage) через `util/Msg`.
   Ни одной захардкоженной строки для игрока в Java. Новый текст = новый ключ.
2. **Логи сервера — только ASCII** (Windows-консоль коверкает не-латиницу).
   Игрокам — MiniMessage; в консоль — ASCII (`DebugLog` уже фильтрует не-ASCII в `?`).
3. **Данные на предметах/сущностях — только PDC** (`util/Keys`). Парсить лор/имена
   запрещено (лор — отображение). Новый ключ регистрируй в `Keys.init`.
4. **Любое изменение блока мира в матче** — сначала `session.rememberBlock(block)`,
   иначе cleanup не откатит. **Заспавненные сущности** — `session.trackEntity(...)`,
   иначе останутся после матча.
5. **Снапшот игрока неприкосновенен**: вход в сессию = `PlayerSnapshot.save` →
   `clear`; любой выход (leave / гибель / cleanup / восстановление при входе на
   сервер) обязан заканчиваться `restore`. Игрок никогда не уносит игровые предметы
   и не теряет свои.
6. **Игровая логика — main thread.** Async — только SQLite (`StatsRepository`).
   Никаких async-обращений к Bukkit API.
7. **GUI — только через `menu/Menu`** (InventoryHolder). Заголовки инвентарей не
   сравниваем.
8. **MiniMessage: плейсхолдеры не должны совпадать с именами тегов** — для чисел
   `<n>` (не `<gold>`), иначе плейсхолдер съест одноимённый тег. **Ключи YAML не
   должны быть голыми `on/off/yes/no`** (парсятся как boolean) — пиши
   `state-on`/`state-off` и т.п.

## Правило шаблона

Это каркас, а не игра. Игровую специфику держи **только** в наследнике `Minigame`
(состояние матча — в `GameSession.data()` / `MatchPlayer`, не в полях `Minigame`).
Расширяешь ядро — расширяй обобщённо, чтобы годилось любой игре. Числа игры — через
`Arena.getSetting/setSetting`, а не новыми полями `Arena`.

## Процесс

- Проверка изменений: `./gradlew deploy -PdeployDir=<server>/plugins` → перезапуск
  сервера → лог без стектрейсов (`[SkyBlockWars] SkyBlockWars enabled`) + ручная проверка фичи.
- После нетривиального изменения — обнови `.memories/STATE.md` (см. `INDEX.md`,
  «Правило поддержки»). Память противоречит коду → прав код, чини память.
