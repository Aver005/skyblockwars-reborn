# 01 — Архитектура

Как устроено ядро MCMGP и почему. Правила конкретной игры сюда не входят — они
живут в наследнике `Minigame` (см. [02-making-a-game.md](02-making-a-game.md)).
Package root: `ru.kiviuly.mcmgp`.

## Ядро модели

```
McmgpPlugin ── bootstrap + wiring; game() возвращает зарегистрированный Minigame
   │
   ├─ ArenaManager ── реестр Arena (arenas/<id>.yml) + Map<UUID, GameSession>
   │     │            (кто где играет) + join()/leave()
   │     └─ Arena ── игро-НЕзависимый конфиг площадки: мир, лобби, спавны, лимиты
   │                 игроков, тайминги + обобщённая settings-мапа (числа игры)
   │                 + ссылка на живую GameSession
   │
   ├─ StatsRepository ── SQLite (wins/loses/kills/played, запись async)
   ├─ Minigame ── ТВОЯ логика (абстрактная; по умолчанию заглушка TemplateGame)
   └─ Msg / Keys / Items / DebugLog ── статические утилиты
```

Три несущих понятия:

- **`Arena`** — статическая конфигурация одной площадки. Знает только общее: мир,
  лобби, точки спавна, `min/max-players`, тайминги. Числа самой игры хранит в
  обобщённой мапе (`getSetting(key, def)` / `setSetting`), чтобы добавлять их без
  правки класса. Один файл на арену: `arenas/<id>.yml`.
- **`GameSession`** — один матч. Создаётся при первом входе игрока в лобби, умирает
  в `cleanup()`. Владеет всем, что живёт и умирает с матчем: список `MatchPlayer`,
  текущая `GamePhase`, таймеры, набор изменённых блоков (для отката),
  заспавненные сущности, `data()` — мапа состояния игры.
- **`Minigame`** — правила твоей игры. Логика **без состояния**: методы-хуки
  получают `GameSession` и работают через его API. Одна инстанция на плагин,
  регистрируется в `McmgpPlugin.onEnable`.

Разделение простое: **ядро ведёт матч, `Minigame` решает, что этот матч значит.**

## Жизненный цикл матча

```
   /mg join  (первый игрок создаёт GameSession)
        │
        ▼
   ┌──────────┐   набран min-players     ┌────────────┐
   │  LOBBY   │ ───────────────────────► │  COUNTDOWN │
   │ ожидание │                          │   отсчёт   │
   └──────────┘ ◄── игроков стало < min ─└────────────┘
        ▲         (отсчёт отменён)              │
        │                                       │ отсчёт вышел
        │                                       │ (короче, если лобби полное:
        │                                       │  countdown-full-seconds)
        │                                       ▼
        │                                 ┌────────────┐
        │  return-to-lobby:               │  RUNNING   │
        │  restore игроков из снапшота     │  матч идёт │
        │                                 └────────────┘
        │                                       │ checkResult(s) != null
        │                                       │ (последний живой / вышло время)
        │                                       ▼
        │                                 ┌────────────┐
        └──────────────────────────────  │  ENDING    │
           cleanup():                     │  итоги +   │
           - откат изменённых блоков       │  cleanup   │
           - удаление tracked-сущностей    └────────────┘
           - restore всех снапшотов
```

Что делает движок на переходах и какие хуки зовёт (`s` — `GameSession`):

| Фаза / переход | Движок | Хук `Minigame` |
|---|---|---|
| Вход в `LOBBY` | снапшот игрока (`save`+`clear`), телепорт в лобби, `ADVENTURE` | `onLobbyJoin(s, p)` |
| `LOBBY → COUNTDOWN` | набран `min-players`; при полном лобби берёт `countdown-full-seconds` | — |
| `COUNTDOWN → RUNNING` | телепорт на спавны, `SURVIVAL`, инвентарь очищен | `onStart(s)`, затем `giveLoadout(s, p)` каждому |
| `RUNNING` (тик 1 Гц) | таймер, обновление HUD | `onTick(s)`; `checkResult(s)` |
| гибель/выбывание игрока | fake death → spectator (если `spectator-on-death`) | `onPlayerEliminated(s, mp)` |
| `RUNNING → ENDING` | зафиксирован `MatchResult` | `onEnd(s, result)` |
| `ENDING` (cleanup) | откат блоков, удаление сущностей, `restore` игроков, возврат в лобби, запись статистики | — |

`checkResult(s)` вызывается ядром и **завершает матч, как только вернёт не-null**.
По умолчанию возвращает `s.defaultResult()` — последний живой игрок, либо ничья,
когда вышло время. Переопредели, если условие победы другое.

## Потоки данных

- **Создание арены**: `/mg create <ID>` → `Arena.create` с дефолтами из
  `config.yml` (`arena-defaults`). Каждое админ-изменение → `Arena.save` в
  `arenas/<id>.yml` (не держим правки только в памяти).
- **Точки арены через маркеры**: `/mg addspawn` выдаёт предмет-маркер с PDC-метками
  (`Keys.MARKER_TYPE/MARKER_ARENA/MARKER_EXTRA`). Игрок ставит блок → `SetupListener`
  ловит установку, читает PDC и записывает точку в арену. Титулы/лор не парсятся —
  только PDC (`SetupMarkers` собирает эти предметы).
- **Снапшот игрока**: `PlayerSnapshot.save` пишет полный снапшот в
  `snapshots/<uuid>.yml` перед входом в лобби; `restore` применяет и удаляет файл.
  Файл на диске = страховка от краша: если снапшот есть, а сессии нет, игрока
  восстанавливают при входе на сервер.
- **Статистика**: `StatsRepository` пишет в `stats.db` (SQLite) в async-задачах;
  `/mg stats` читает. Колонки — `wins/loses/kills/played` на игрока.
- **Тексты**: всё игрокам — из `messages.yml` через `Msg` (MiniMessage). Дефолты
  зашиты в jar, поэтому новые ключи работают без ручного слияния после обновления.

## Откат мира и игроков

Два инварианта держат обещание «после матча мир и игроки — как до него»:

- **Мир.** Перед ЛЮБЫМ изменением блока в матче его прежнее состояние кладётся в
  сессию: `session.rememberBlock(block)`. Любая заспавненная сущность —
  `session.trackEntity(entity)`. `cleanup()` в `ENDING` откатывает блоки и удаляет
  сущности. Не запомнил — не откатится.
- **Игрок.** Вход в сессию = `PlayerSnapshot.save` + `clear`. Любой выход
  (leave / гибель / cleanup / восстановление при входе на сервер) заканчивается
  `restore`. Игрок никогда не «уносит» игровые предметы и не теряет свои.

## Потоки и многопоточность

Вся игровая логика — **main thread**. Единственное исключение — SQLite
(`StatsRepository` пишет в async-задачах). Никаких async-обращений к Bukkit API,
никакого Folia-шедулинга.

## Где что лежит (runtime)

Данные плагина — в `plugins/MCMGP/`:

```
plugins/MCMGP/
├── config.yml            общие числа/флаги (см. 03-commands-and-config.md)
├── messages.yml          ВСЕ тексты игрокам (MiniMessage)
├── arenas/<id>.yml       по файлу на арену
├── snapshots/<uuid>.yml  снапшоты игроков в матче (обычно пусто вне матчей)
├── logs/debug-*.log      выгрузки /mg debuglog save
└── stats.db              SQLite-статистика
```

Раскладка исходников по пакетам — в таблице [README](../README.md#структура-пакетов).
